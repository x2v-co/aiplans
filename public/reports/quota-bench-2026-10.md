## 如何处理控制会话干扰

只比较现有登录信息中的 account_id 与官方桌面接口账户标识，确认 CLI 和本聊天共用账号，没有保存或输出密钥。当前聊天的本地 turn_context 确认为 gpt-6-astra。后续 bench 固定同一模型；以本聊天 token_count 的累计差值建立单独的 control-ledger.json，覆盖测量起止之间的 33 条新增用量记录，验证计数单调、模型没有改变。中间看到控制会话有消耗的区间，没有标为“静默隔离成功”。

这使已知控制消耗可审计，而非错误归为纯 bench。仍未获得服务商全账户请求审计，不能完全排除其他设备调用；也不能把客户端日志时间当作服务端计费入账时间。延迟复读稳定只能提高可信度，不能证明服务商永无更长延迟。

## 结果与误差

按本次真实组成（缓存读取占约 66.3%）线性外推，同组成总 tokens 约 **1.770 亿 / 周窗口**。若两端整数读数各有 ±0.5 个百分点误差，实际消耗为 4–6 个百分点，对应约 **1.475–2.212 亿 tokens / 周窗口**。这个数包含控制会话形成的高缓存比例，不能当成纯新输入额度或任何工作负载的固定上限。

[OpenAI 官方 Astra 模型页](https://developers.openai.com/api/docs/models/gpt-6-astra) 当前标准 API 价格为每百万 tokens：输入 $10、缓存读取 $1、缓存写入 $12.50、输出 $50；超过 272K 输入的请求适用更高价格。本段记录均不触发该长输入阈值，缓存写入为 0。按标准 API 标价估值（不是订阅内部计费事实）：

(2,961,487 × 10 + 5,864,960 × 1 + 23,296 × 50) / 1,000,000 = **$36.64463**。

$36.64463 / 5% = **约 $732.89 / 周窗口**。

仅由整数读数造成的范围为 **$610.74–$916.12**。这不是统计置信区间、现金余额、承诺可用额度或跨模型通用兑换率。模型服务模式、服务商内部权重、并发与结算延迟可能带来额外误差。公开标价仅用于把观测到的 token 组成换成一致参考单位，不证明套餐按 API 标价扣量。

本次累计周读数轨迹为：主阶段 47 → 47 → 48 → 49 → 49 → 50 → 50 → 51 → 51 → 52；每批 4 个请求。原始比例与每批用量均保留，可复算每个前缀。本轮已经取得真实容量估算，精度仍受整数仪表盘限制，作为条件实测记录公开，不是官方套餐承诺。

## 文件与复算

- normalized-ledger.json：60 次调用的分类 token 与模型标签。
- control-ledger.json：Codex 同账号控制会话的分类用量，不包含聊天内容或凭据。
- results.json：最终计算；analysis-current.json：计算时快照。
- 每个 codex-*/run-*、cursor-*/run-*：原始事件、错误日志和摘要；各 Codex 批次另有前后额度、控制计数。
- codex-final-recheck-*.json：停止 bench 后复读。
- cursor-meters.json：已成功采集的精细页面读数。
- prices-astra.json：Astra 公开价参考；validation.json：60 份原始事件复算校验。
- batch.py、codex-series.py、analyze.py：本地运行与复算脚本。运行期模型、等待时间有调整，manifest.json 和本报告说明阶段差异；这些是实验脚本，尚未集成为生产 adapter。
