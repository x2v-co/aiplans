# 套餐额度实测默认规则

2026-10-28，经用户确认，适用于后续所有套餐的真实额度实测。

1. **所有可用周期一起测。** 同一轮同时采集服务商可读取的所有窗口（如 5 小时、日、周、月），用同一批请求的 token 账本分别计算，不能只选择一个周期。
2. **完整记录每个窗口。** 测试前、每批结束及停止调用后的延迟复读都记录用量、观测时间和可获得的重置信息。发生重置时分段计算，不跨重置直接相减。
3. **优先提高短周期和周额度精度。** 根据扣量信号和读数精度调整样本量，比较不同批次的结果；仍遵守本轮约定的预算和停止条件。
4. **长周期也保留结果。** 月等长周期信号较弱时给出有依据的粗估和误差说明。零变化、无法读取或不足以给出有限区间时，标注无法估算、仅能给出边界或不可用，不编造数值。
5. **分别估算，不按时间倍数换算。** 每个窗口使用自己的已用比例增量；多个限制同时生效，容量不能相加。
6. **保留负载和不确定性。** 记录模型、普通输入、输出、缓存读取及写入。单一配比结果不能推广为跨模型固定 token 上限。舍入误差区间不等于整体准确率或统计置信区间；并发流量、结算延迟、内部权重与账号档位的不确定性需单独说明。
7. **数据和报告一同发布。** 套餐卡片并列展示各窗口的估算或不可估算状态；详情链接提供过程、原始读数、脱敏逐次账本及计算依据。新报告注明所替代的历史结果。

## 同套餐多模型评测

2026-10-28 用户确认：其他 plan 默认参考火山多模型实测方式。

- **覆盖主力模型。** 根据套餐实际提供的模型和用户常用模型选择覆盖范围，不能只测默认模型就代表整个套餐。先完成一个基准模型，再分别校准其他主力模型；未测模型明确标为未测。
- **模型独立、周期同步。** 每个模型单独建立起止读数、逐次账本和实际配比，同时采集该套餐所有可读取周期。共用额度池时，不并发测试不同模型；停止调用、复读稳定后再切换。
- **实际响应为依据。** 保存请求模型名与响应模型标识；发生路由切换、回退或无法确认模型时，不把请求名当作已验证的实际模型。支持按请求指定模型时优先使用，避免改变账号默认配置。
- **按信号追加样本。** 主力模型至少比较多个批次；消耗较低的模型可以扩大样本，但仍遵守预算和停止条件。周和月变化较小时公开舍入边界或不可估算状态，不用 API 标价比例代替实测扣量。
- **输入长度和配比分组。** 分别记录普通输入、输出、缓存读取与写入；明显不同的上下文长度或负载配比单独建组。扩大输入后若单位 token 扣量发生变化，保留试测并单独计算，不能混合生成貌似精确的统一容量，也不能据此直接认定服务商加价阈值。
- **直接展示模型对照。** 卡片按模型及必要的负载场景列出各周期结果，标注样本数、输入配比、长输入条件、粗估或误差；报告提供完整过程和账本。共享额度池的各模型容量不能相加。

这是实测与发布流程要求，不代表所有服务商的额度接口或多周期采集已自动化。接口不可用时可记录已登录控制台的可见读数，并注明来源与显示精度。
