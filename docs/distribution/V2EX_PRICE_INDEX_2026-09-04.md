## 正文

最近在做 AI 应用成本评估时，我遇到一个反复出现的问题：同一个模型可能同时出现在
官方 API、云厂商和聚合平台上，但币种、缓存、批处理、免费路由和模型别名的口径并不
一致。只把页面上的输入单价抄到一张表里，很容易得到一个看似精确、实际不可复算的
结论。

于是我做了一个可搜索、可筛选的 AI API 价格索引。目前快照包含：

- 343 个有价格的模型；
- 479 个当前可用渠道；
- 21 家提供商。

现在的处理原则是：

1. 比价前先对齐精确模型 ID，不把不同版本混在一起；
2. 保留渠道原始结算币种，只在跨渠道排序时换算成美元；
3. 输入、输出、缓存和批处理价格分开记录；
4. 免费路由不参与“最低付费价格”的选择；
5. 每个价格保留来源和最近核验日期；
6. 示例成本统一按 100 万输入 token 加 25 万输出 token 计算，方便复算。

页面在这里：

https://aiplans.dev/zh/reports/api-price-index?utm_source=v2ex&utm_medium=community&utm_campaign=pricing_research_2026_09&utm_content=price_index

项目和数据处理逻辑是开源的：`https://github.com/x2v-co/aiplans`。

我是这个项目的维护者。这次更想收集下面几类反馈：

- 哪些模型别名被错误地合并或拆开了？
- 国内渠道的币种、地区或支付限制有没有漏记？
- 缓存和 Batch 价格应该怎样展示才不容易误导？
- 哪些渠道已经下线，或者价格明显过期？

如果发现问题，最好附官方定价页或文档链接，我会按来源重新核验。
