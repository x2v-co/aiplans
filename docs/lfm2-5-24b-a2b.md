The model is open-weight, text-to-text, reasoning-only, and supports tools and

OpenRouter reports 2.45B active. The model row uses Liquid's context and parameter
figures. The repository's `open_source` flag also represents open-weight access
(as in `seed-vertical-models.ts`); this does not assert an OSI license.

OpenRouter's maximum completion is 8,192 tokens. This is a route limit, so the
seed records it in the model description rather than setting a global
`max_output_tokens` limit for Liquid Console. There is no context or completion
column on `api_channel_prices`. The OpenRouter scraper captures context in its
scraped result and endpoint variant constraints; it does not update existing
model context. The official model context therefore remains 131,072.

## Ingestion decision

`scripts/scrapers/openrouter.ts` has no model/provider allowlist. Its provider
normalization map falls back to the original provider string, so `liquid` needs
no entry. This listing has valid token prices and text output, passes the
filters, and gets headline pricing plus default-route and Liquid endpoint
variants. The existing OpenRouter channel maps to provider ID 59.

However, `scripts/index-dynamic.ts` infers producer IDs from model names and
restricts automatic model creation to its official provider ID list. Liquid has
no producer mapping there. Unknown producers use an exact slug lookup (or an
existing slug redirect), and the runner skips the price when no model exists.
Thus OpenRouter **will ingest the channel after this seed creates the model**;
it will not create this model independently on a fresh catalog.

There is no Liquid provider definition or Liquid official scraper in the
repository. No production DB was queried to establish live row presence. The
seed resolves `liquid` by slug, reuses an existing official/producer row, or
creates an official Liquid Console provider. It then creates/corrects the model
and official channel using `scripts/data/lfm2-5-24b-a2b.ts`. OpenRouter prices
are omitted from the seed because subsequent successful OpenRouter scrapes
maintain them. Liquid official pricing needs this seed and future verified
updates until an official scraper exists.

`scripts/scrapers/modelsdev.ts` supplies external audit reference prices and
plan entitlements; it does not insert model/channel rows. A scoped OpenRouter
alias maps this catalog slug to the models.dev API-ID key when that listing is
present. There is no verified Liquid official provider profile in this adapter,
so Liquid Console is not cross-checked against OpenRouter's different prices.
The models.dev API returned HTTP 403 during this implementation; the audit
alias is tested with a fixture, not a claim that the live catalog contains it.
No change to the model normalizer or identity guard is needed; the seed's name
and slug pass the guard.

## Rollout

Merging the code into `main` triggers the production deployment workflow.
Deployment does not run this seed. There is no schema migration for this change.
The Argon seed has no npm script entry, so this seed likewise uses direct `tsx`
commands.

1. After deployment, SRE runs the default dry run against the intended DB and
   shares its field-level plan with the owner:

   ```bash
   npx tsx scripts/seed-lfm2-5-24b-a2b.ts
   # Equivalent explicit mode:
   npx tsx scripts/seed-lfm2-5-24b-a2b.ts --dry-run
   ```

2. The owner confirms the provider, model identity, official prices, and planned
   changes. Only then does SRE execute:

   ```bash
   npx tsx scripts/seed-lfm2-5-24b-a2b.ts --apply
   ```

3. The next successful scheduled OpenRouter scrape resolves the model and
   publishes its headline price and endpoint variants. SRE can run the seed dry
   run again to confirm no further seed changes, then check the model page for
   both channels and the successful OpenRouter scrape status.

The dry run uses a serializable read-only transaction; writes require `--apply`
and happen in a single serializable transaction after the full plan is checked.
Null dependency IDs in the printed plan mean IDs returned by provider/model
inserts. Existing Liquid metadata is retained. Unexpected provider types,
alternate model slugs, or duplicate official channel rows abort for review
without writing. Changed rows receive `updated_at`; equal rows are left alone.

No production DB access or seed execution with `--apply` was performed during
implementation. Local validation uses pure data tests and mocked scraper fetches.
