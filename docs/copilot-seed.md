After the existing channel-terms migration is deployed, SRE can run with the intended database configuration:

```sh
npm run seed:copilot         # default: read-only transaction, field-level preview
npm run seed:copilot:apply   # explicit: serializable transaction, idempotent writes
```

The seed reuses GitHub's provider/product ID, protects unrelated records and manual model links, and writes derived preview-pool links only for models already in the catalog. Missing models are skipped; rerun after catalog additions or use the usual mapping materializer. If no pool model exists, the selector remains NULL until the seed is rerun. The default dry-run sets the same serializable transaction read-only and issues SELECTs only. No database was accessed as part of this refresh; tests use an in-memory SQL fixture.

## Schema gap

The current fields cannot encode a monthly **per-user seat fee plus a shared, model-priced enterprise usage budget**, organization-wide credit pooling, the GHE license dependency, enterprise-wide billing-model exclusivity, staged sales availability, or which features survive budget exhaustion. These conditions are recorded in notes/features rather than adding schema or inventing a new billing enum.

Standalone keeps `pricing_model=subscription`, `price_unit=per_month` and supported `billing_granularity=flat_monthly` for the seat fee only. `is_contact_sales=false` exposes the published $10 seat price on price cards; sales-assisted availability remains in the sourced notes/features. `included_credits=0`, `included_usage_amount=0`, and `quotas=[]` explicitly convey no included allowance; the economics helper returns `none_published` and computes no usage-per-dollar rate. `monthly_api_credit_usd` and `monthly_api_credit_status` stay NULL: Copilot usage is not an included external API balance, and `needs-verification` would incorrectly trigger copy saying that monthly API credit is included. Business/Enterprise credit quotas are per-user contributions; their organization-wide pooling is explained in the quota notes. Sources: [announcement](https://github.blog/changelog/2026-10-28-github-enterprise-now-includes-access-to-github-copilot), [billing comparison](https://docs.github.com/en/copilot/get-started/whats-changing-with-github-enterprise-and-copilot), [plan documentation](https://docs.github.com/en/copilot/get-started/plans); verified 2026-10-29.

**Ranking caveat (repository audit, 2026-10-29; no database access):** the existing data already gives Pro `tier_rank=1` and Standalone `tier_rank=6`. Preserve these ranks and the enterprise tier: `src/app/[locale]/providers/[slug]/page.tsx:getPlansByProvider` and `src/lib/compare-plans.ts:getPlanComparison` order the GitHub line by rank, and their strict-less-than cheapest selectors keep Pro on the $10 tie. The two plans have the same preview-pool mappings, so Pro also precedes Standalone in that pool's comparison summaries. No new ordering change is needed for these ties. This is a seat-price tie, not equal included usage: Pro has 1,500 monthly AI credits and Standalone has none. Source: [plans](https://github.com/features/copilot/plans), [billing comparison](https://docs.github.com/en/copilot/get-started/whats-changing-with-github-enterprise-and-copilot); verified 2026-10-29.

There is no existing general ranking-exclusion flag consumed by these selectors. They do not inspect `included_credits=0` or `quotas=[]`. Changing rank cannot fix callers that ignore it; changing price, tier, official status, billing unit, product line or model mappings to suppress the row would misrepresent the offer.
